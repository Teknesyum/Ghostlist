## Amaç
**Canlı sürümde yanlış pozitif var.** v2.0.0 gerçek bir makinede çalıştırıldı ve Türkçe
karakter içeren kısayol hedefleri bozuk okundu:

```
[broken 95] shortcut  HWiNFO64 - Kısayol
    - shortcut_target_missing  C:\Users\Administrator\Desktop\K?sayol\hwi_835_5890\HWiNFO64.exe
```

Dosyanın kendi yolu (`Kısayol`) doğru; `.lnk` **içinden** çözülen hedef bozuk (`K?sayol`).
Bozuk yol diskte bulunamıyor, bulunamayınca "kaldırıcı/hedef yok" kanıtı üretiliyor,
iki kanıt birleşince güven 95 çıkıyor ve bulgu **otomatik toplu düzeltmeye giriyor**.

Yani var olan bir kısayol, sırf yolunda Türkçe harf olduğu için siliniyor. Bu ürünün
kaçınmak için en çok emek harcadığı hata sınıfı ve Türkçe kullanıcıda sistematik tetikleniyor.

## Kök neden
`ShellLinkReader.cs:58` → `Encoding.Default.GetString(...)`. .NET Core/8'de `Encoding.Default`
**her zaman UTF-8**'dir; `.lnk` biçimindeki ANSI dizeler ise sistem ANSI code page'indedir
(Türkçe Windows'ta Windows-1254). UTF-8 olarak çözülünce `ı`, `ş`, `ğ`, `ç`, `ö`, `ü` bozulur.

## Kabul kriteri
1. **ANSI dizeler doğru code page ile okunur.** .NET 8'de bunun için
   `CodePagesEncodingProvider.Instance` kaydı gerekir (`System.Text.Encoding.CodePages`).
   Sistem ANSI code page'i alınır (`GetACP` / `CultureInfo`), o kod sayfası kullanılır.
   Kod sayfası alınamıyorsa Windows-1252'ye düş, **UTF-8'e düşme**.
2. **Unicode yol tercih edilir.** `.lnk` başlığındaki `LinkFlags`'te `IsUnicode` biti varsa
   dizeler zaten UTF-16'dır. Ayrıca `EXTRA_DATA` bloklarında Unicode yol taşıyan alanlar
   bulunur. **Unicode varsa her zaman o kullanılır**, ANSI yalnızca geri düşüş yoludur.
3. **Çözülemeyen kodlama bulgu üretmez.** Yol güvenle çözülemiyorsa kısayol atlanır ya da
   en fazla `Suspicious` olur — **asla `Broken` olmaz**. Şüphedeysen bulgu üretme kuralı
   burada da geçerli: silinmemesi gereken bir şeyi silmektense hiç bulmamak yeğdir.
4. **Testler gerçek `.lnk` baytlarıyla.** Testte gömülü bayt dizisi olarak en az üç örnek:
   ANSI + Türkçe karakterli hedef, Unicode bayraklı hedef, bozuk/kesik dosya.
   Türkçe olan test, düzeltme öncesi **kırmızı** olmalı — hatayı gerçekten yakaladığını
   böyle kanıtlarsın. Çıktı'ya bunu doğruladığını yaz.
5. **`StartupProvider` de kapsanır** (`StartupProvider.cs:99` aynı okuyucuyu kullanıyor).
   Kısayol dışındaki yollarda da (registry `Run` değerleri, görev XML'i) benzer bir
   kodlama varsayımı var mı, kontrol et; varsa Çıktı'ya yaz — düzeltmesi bu sözleşmede değil.
6. **Sürüm `2.0.1`.** `Directory.Build.props` güncellenir. `packaging/winget/` üç dosyadaki
   `PackageVersion` ve `InstallerUrl` de 2.0.1'e çekilir; `InstallerSha256` **yeniden
   64 sıfır** yapılır (yeni yayın olmadan hash bilinemez). README'deki sürüm satırı güncellenir.
7. `dotnet build -c Release` 0 uyarı, tüm testler yeşil (283 + yenileri). Commit atılır.

## Çıktı
1. Kök neden `Encoding.Default.GetString` (UTF-8) idi. `ShellLinkReader.cs` artık
   `CodePagesEncodingProvider` ile sistem ANSI code page'ini (`GetACP`, düşüş: `CultureInfo`,
   son düşüş: 1252) kullanıyor; UTF-8'e hiç düşmüyor.
2. LinkInfo'da Unicode alanları (`LocalBasePathOffsetUnicode`/`CommonPathSuffixOffsetUnicode`)
   dolu ise (offset != 0) her zaman onlar tercih ediliyor, ANSI yalnızca geri düşüş.
3. Kod sayfası çözülemezse (`AnsiEncoding is null`), decoder istisna fırlatırsa, ya da
   çözülen dize tanımsız-eşleme belirtisi taşıyorsa (U+FFFD veya C1 kontrol aralığı
   U+0080–U+009F — Windows ANSI code page'lerinde tanımsız baytların düştüğü yer)
   `ShellLinkTarget.IsAmbiguous = true` dönüyor. `ShortcutProvider.Inspect` ve
   `StartupProvider.ScanFolders` bu durumda bulguyu tamamen **atlıyor** (ne Broken ne
   Suspicious) — silinmemesi gereken bir şeyi silmektense hiç bulmama kuralına uydum.
4. **Türkçe karakterli test düzeltme öncesi gerçekten kırmızıydı, doğruladım.** Eski
   koddaki `Encoding.Default.GetString` (yani UTF-8) ile aynı bayt dizisini
   (`0x4B,0xFD,0x73,0x61,0x79,0x6F,0x6C` = cp1254 "Kısayol") ayrı bir konsol projesinde
   çalıştırdım: çıktı `K�sayol` — beklenen `Kısayol`'dan farklı, yani test eski kodla
   FAIL ederdi. Düzeltme sonrası `AnsiTurkishTargetIsDecodedWithTheSystemCodePageInsteadOfUtf8`
   testi geçiyor. Diğer üç test: `UnicodeLinkInfoFieldsAreUsedInsteadOfTheAnsiOnes`
   (Unicode alanı varken ANSI alanına değil ona bakıldığını kanıtlar),
   `TruncatedLinkInfoProducesNoTarget` (kesik dosya → null, exception yok),
   `UndecodableAnsiBytesAreAmbiguousInsteadOfMisread` (cp1254'te tanımsız 0x81 baytı →
   `IsAmbiguous=true`, `LocalPath=null`) — dördü de `Ghostlist.Tests/ShellLinkTests/
   ShellLinkReaderEncodingTests.cs`.
5. `StartupProvider.cs` kapsandı (`ScanFolders`, eski satır 99). `ScanRegistry` yolu
   `RegistryKey.GetValue` ile geliyor — .NET registry API'si zaten doğru UTF-16 string
   döndürüyor, ANSI/UTF-8 varsayımı yok, ek düzeltme gerekmedi. `UninstallCommandParser`
   ve görev XML'i (`TaskProvider`) tarandı, `Ghostlist.Core` içinde
   `Encoding.Default`/ANSI varsayımı yalnızca `ShellLinkReader.cs`'deydi — başka yerde yok.

   `installer.yaml`'de `InstallerUrl` (v2.0.1 tag'ine), `InstallerSha256` 64 sıfıra
   çekildi. `README.md` sürüm satırı güncellendi.
