## Amaç
İki iş: (a) ikili "Bozuk / Sağlam" damgasını **kanıt tabanlı** bir modele çevirmek,
(b) bugün pes edilen iki büyük kategoriyi kazanmak — MSI yetimleri ve MSIX/UWP paketleri.
Ayrıca T4'ün üstüne bineceği `IIssueProvider` soyutlamasını burada açmak.

## Kabul kriteri
1. **Kanıt modeli.** `Finding` başına kanıt listesi (`Evidence(Kind, Detail, Weight)`).
   Örnek kanıtlar: uninstaller dosyası yok · `InstallLocation` klasörü yok · `DisplayIcon`
   hedefi yok · MSI ürün kaydı yok · MSI cache paketi yok. Sonuç `Confidence` (0-100) ve
   `EntryStatus`. Eşikler tek yerde sabit olarak dursun, koda serpilmesin.
2. **Silme eşiği katı kalır.** Otomatik düzeltme yalnızca `Confidence >= 90` **ve** en az
   iki bağımsız kanıt varken önerilir. Tek kanıtla `Broken` damgası basılmaz.
3. **MSI yetimleri.** `msiexec` görünce artık pes edilmez. ProductCode (T2'nin
   `ResolveMsiProductCode`'u) ile: `HKLM\SOFTWARE\Classes\Installer\Products\<packed>` kaydı
   ve `%WINDIR%\Installer\<…>.msi` cache paketi aranır. İkisi de yoksa yetim MSI kaydıdır.
   Packed GUID dönüşümü (ProductCode ↔ 32 haneli sıkıştırılmış biçim) testli olsun.
4. **MSIX/UWP.** Ayrı sağlayıcı: staged olup manifesti veya kurulum klasörü kayıp paketler.
   Registry silme **yapma** — bu kategoride önerilen eylem `Remove-AppxPackage` komutunun
   kullanıcıya gösterilmesi. Otomatik çalıştırma yok.
5. **`IIssueProvider`.** `string Id`, `string Category`, `IReadOnlyList<Finding> Scan()`,
   `FixResult Fix(Finding, IBackupSink)`. Mevcut uninstall taraması bu arayüzü uygulayan
   `UninstallEntryProvider`'a taşınır. `CleanupService` sağlayıcı listesi üzerinden çalışır,
   tek tipe bağlı kalmaz.
6. Sistem bileşeni ve çözülemeyen komut korumaları aynen durur — gevşetme.
7. Testler: kanıt→skor eşlemesi, packed GUID, MSI yetim kararı, MSIX kararı. `dotnet test` yeşil.

## Arayüzler
T4 ve T5 bunlara dayanacak:
```csharp
public interface IIssueProvider { string Id { get; } string Category { get; }
    IReadOnlyList<Finding> Scan(); FixResult Fix(Finding finding, IBackupSink backup); }
public sealed record Evidence(string Kind, string Detail, int Weight);
public sealed record Finding(string Id, string Title, string? Subtitle, EntryStatus Status,
    int Confidence, IReadOnlyList<Evidence> Evidence, string ProviderId, object Payload);
```
T2'den gelen: `ResolveExecutable(command, view, installLocation)`, `ResolveMsiProductCode(command)`.

## Bağlam
- `EntryClassifier.cs` bugün 21 satır ve tek kural: dosya var mı. Kanıt modeli bunun yerine geçer.
- `UninstallEntry` kaydı `Models.cs`'te; `IsSelected` mutable property'si UI'ın kullandığı
  tek yazılabilir alan — `Finding`'e taşırken koru.
- `StatusText` bugün Türkçe sabit döndürüyor. **Core'da kullanıcı metni bırakma:** durum
  ve kanıt için dil-bağımsız anahtar üret, çeviri T5'in işi. Bu kritik, T5 buna bağlı.
- T2'nin `RegistryBackup` genişletmesi `RegistryRepository.cs`'te tanımlı olabilir; `Models.cs`
  senin sahipliğinde, oraya taşımak istersen taşı ama T2'nin testlerini kırma.
- MSI cache dizini `%WINDIR%\Installer` erişimi yönetici gerektirebilir; erişilemezse bu
  kanıt "belirsiz" sayılır, "yok" sayılmaz. Yanlış pozitif üretme.
